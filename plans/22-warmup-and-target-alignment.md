# 计划 22：修组合引擎的"指标预热段"缺口 + 单标的实验标的统一到能买的基金

起因：用户先跑 `STRATEGY = ["bottom_reversal"]`（标的默认"上证指数"），
再跑 `STRATEGY = ["longterm_balance", "bottom_reversal_fund"]`，发现
"同一个 bottom_reversal 策略，年化 5.1% 和 5.26% 不一样"，问 bug 在哪。

## 诊断：两个问题被一个现象盖住了

排查方式是**把变量一次只换一个**，补跑中间那一行（同策略、同区间、同成本，标的换成基金）：

| 跑法 | 标的 | 引擎 | 总收益 | 年化 |
|---|---|---|---|---|
| 用户第 1 次 | 上证指数 idx:000001 | 单标的 engine.py | +49.5% | 5.10% |
| **补跑（新增）** | 基金 fund:100053 | 单标的 engine.py | +49.5% | 5.10% |
| 用户第 2 次 | 基金 fund:100053 | 组合 portfolio.py | +51.2% | 5.26% |

- **第 1→2 行（换标的）**：总收益碰巧同为 +49.5%，但逐笔明细完全不同
  （2019-08-13 vs 2019-08-09 进场；原版做 2019-01/2023-06，基金版换成 2020-11/2024-01）
  → 净效果为零纯属巧合，不能因此说"标的不影响"。真正显出差别的是买入持有对照：
  **上证指数 +37.4% vs 基金 +76.0%**（同期）。
- **第 2→3 行（换引擎）= 真 bug**：标的已经统一，还差 1.7pp。

## bug 本体：组合引擎不给指标喂预热段

`quant/portfolio.py` 原来是 `hist=bt.iloc[:i + 1]`，而 `bt = px.loc[bt_start:]`
——策略每天看到的历史**从回测起点当天才开始**。后果：

- 2018-07-09 只有 6 行历史，RSI6 要 7 行 → 那天的真信号算不出来，被**静默漏掉**
- 漏掉这笔 → 10 日冷却期跟着错位 → 组合版反而做了单标的版被冷却期屏蔽的 2018-08-08 那笔
- 首笔之后 21 笔逐日对齐，差额全部来自这一处：漏掉的那笔亏 -1.7%，换来的那笔只亏 -0.5%

单标的引擎没这问题，因为 `run_experiment` 的 `data_start="20180101"` 比 `start` 早半年，
天然有暖机段。**两套引擎对"策略能看多少历史"的约定不一致，这才是 bug**——
不是回测区间不一致（两边都是 2018-07-01 起）。

## 修法（一行 + 一处准备）

```python
warm = px.loc[first_full:, names]     # 全员就绪日起的完整历史（预热段在这里）
...
hist=warm.loc[:date]                  # 每天只切到当天 → 不含未来
```

- 起点用 `first_full`（全员都有数据的首日）而不是 `px` 首行：更早的行里未上市成分是
  NaN，`ffill` 填不了最前面的空洞，会把 NaN 喂给策略。
- **不引入未来函数**：`warm` 是全历史，但每天 `.loc[:date]` 切到当天为止。
- 配套纪律：配方的 `data_start` 要往前留够历史（`bottom_reversal_fund` 写 `20110101`），
  否则取数阶段就没那么多历史可暖机。

## 修完的验证

- `test_portfolio.py` 9 项全绿、`test_framework.py` 全绿
- `bottom_reversal_fund`：+51.2%/5.26% → **+49.5%/5.11%**，首笔回到 2018-07-10，
  与单标的引擎跑同一只基金**完全对上**（5.11% vs 5.10%，残差是成本扣法舍入：
  engine 把成本折进成交价，组合引擎按金额扣）
- 影响面只有这一个配方：`longterm_balance` 仍 +139.0%/11.42%（阈值再平衡只看最近两天），
  `grid_3tier` 仍 +57.7%/7.19%（科创50 2020-01 才上市，本来就没有预热段可给）
- 附带修正（顺带受益）：网格的"3 年前高"闸门以后能真的回看 3 年，
  而不是从回测起点才开始数——只是这次的标的没触发差异

## 标的统一：单标的实验默认跑基金，不跑指数

`run.py` 的 `TARGET` 从 `"上证指数"` 改成 `"fund:100053"`（富国上证指数ETF联接A）。两个理由：

1. **可执行性**：用户没有 A股账户，指数买不了，跑出来的收益不可落地
2. **准确性**：上证指数是**价格指数**（成分股分红后指数直接往下掉，不含股息），
   基金净值把分红做了再投资 → 同期买入持有 +37.4% vs +76.0%，差 38pp。
   **拿指数回测的收益去估基金，会系统性低估**

指数保留用途：研究市场本身（找底部特征、算涨跌统计）——plans/09 提炼规则用指数是对的，
错的是**把指数上的收益数字当成这个策略的成绩记进档案**。

已重刷的档案数字（全部改为 fund:100053 口径）：

| 文件 | 旧（上证口径） | 新（基金口径） |
|---|---|---|
| `strategies/bottom_reversal.py` note | 年化 5.1% / 回撤 -12.2% | 年化 5.1% / 回撤 -11.9%，**并注明同期买入持有 +76.0%** |
| 同上 区间警告（2013-08 起） | 年化 +1.55% / 回撤 -31.3% | 年化 **+0.9%** / 回撤 **-34.8%**，同期买入持有 **+159.1%** |
| `portfolios/bottom_reversal_fund.py` note | 引用上证原版 5.1% | 自身实测 +5.11%，对照不再平衡 +75.4% |

## 结论层面的变化（重要，不只是数字变漂亮）

补上买入持有对照后，这个策略的评价要下调：**2018-07 起 +49.5% vs 买入持有 +76.0%，
2013-08 起 +12.9% vs +159.1%**。它换来的是更浅的回撤（-11.9% vs -21.3%），
本质是"约 2/3 时间空仓"的低暴露，而不是选点能力。
`bottom_reversal` 现在的定位：**不建议作为主策略实盘**，留作研究底部特征的工具。

## 回测自检（对照 [backtest_checklist.md](../Knowledge/backtest_checklist.md)）

- 未来函数：✓ `warm.loc[:date]` 每天切到当天；订单仍 T+1 成交；`test_portfolio.py` ⑧
  逐日核对 `ctx.hist.index[-1] == ctx.date`（59 天）
- 口径一致性：✓ 本计划就是修这一项——同规则同标的两套引擎现在能对上
- 过拟合：✓ 没有调任何参数；修的是"策略能看到的数据量"，不是规则
- 对照基准：⚠ 这次才发现档案里一直没记买入持有对照 → 结论从"年化 5.1% 还行"
  变成"跑输躺着不动"。**没有对照的收益数字等于没有信息**
- 样本量：21 笔 < 30，两个版本 1.7pp 的差距其实小于单笔噪声——但"两边对不上"这件事
  本身与样本量无关，必须修

## 踩坑 / 教训

1. **"两个数不一样"要先分清是"不该一样"还是"该一样却不一样"**：这次两者同时存在，
   换标的本来就该不一样（不是 bug），换引擎该一样却不一样（是 bug）。
   一次只换一个变量、补跑中间那一行，两分钟就分开了。
2. **已知差异写进文档 ≠ 可以不修**：`adapter.py` 头部早就写着"预热段两边不同，
   别当成 bug"。但它让同规则的两个数永远对不上，等于永久性地放弃了一个交叉验证手段。
3. **收益数字必须连着"标的 + 区间 + 对照"一起记**，缺一个就会误导：
   这条策略同时栽在标的（指数不含股息）和区间（2013 起收益消失）上。
