# 08 报告区分"期末仍持仓"状态

| | |
|---|---|

| 完成 | 2026-07-25 |

## 背景与目标

用户用短区间（2026-06/07 起）跑 bias_oversold 时发现：信号触发、已买入、期末仍持仓，
但报告只显示"信号 1 次 → 成交 0 笔 / 无交易（信号从未触发或被冷却期挡住）"，
措辞误导（用户当场怀疑是 bug）。

**目标**：报告如实区分四种期末状态——无信号 / 持仓中 / 信号待成交 / 信号被挡。

## 验收标准

- [x] 持仓中时报告写明：买入日、买入价、持有天数、浮盈（按末日收盘估值、未计入统计）
- [x] 0 笔闭环时胜率/平均每笔/盈亏比显示 "—" 而不是 "nan%"（与 compare_table 口径一致）
- [x] `python test_framework.py` 全绿（引擎行为零变化）
- [x] 每模块 <150 行约束不破

## 改动方案（关键决策）

- **引擎**：新增 `run_backtest_ex` 返回 `(trades, eq, tail)`，tail 含
  `position / pending_buy / unrealized`；`run_backtest` 改为薄包装丢弃 tail。
  **为什么不改 run_backtest 返回值**：它已被 test_framework / compare_index_bias /
  param_sweep 等多处二元解包调用，改返回值=全链路破坏；加函数=零破坏。
- **报告**：`print_report` 加可选参数 `tail=None`（向后兼容），汇总行改为
  "闭环 N 笔＋期末持仓中 1 笔"，末尾分支按四种状态如实输出。

## 笔记

- 引擎期末"不强制平仓、trades 不含未平仓"的设计是对的（强制平仓=美化结果），
  缺的只是把持仓状态**暴露**出来——设计没改，只加了出口。
- 用户这次"先怀疑 bug 再要证据"的反应值得保持：报告数字反常时，用数据还原时间线
  （本次还原：07-17 信号 → 07-20 买入 @3791.66 → 持有中浮盈 +0.5%）。
